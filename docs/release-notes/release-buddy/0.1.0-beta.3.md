# Release Buddy 0.1.0-beta.3

Release Buddy now focuses its release-integrity guidance on public GitHub projects using signed source tags and immutable releases. Versioning and changelog guidance remains available independently.

- Follow a smaller release process: identify the version's source, verify the authorized tag signer, prepare and review a draft, then publish and verify the immutable release.
- Add build provenance when the project distributes a primary built artifact, and scoped dependency-scan evidence when appropriate. The guidance distinguishes source signatures, release attestations, build provenance and vulnerability reports, including what each can and cannot establish.
- Use revised maintainer and consumer documentation templates, with checks for release identity, artifact digests and recovery from interrupted publication.

This beta removes the bundled npm, PyPI, container and generic release-asset workflow templates. Registry publishing setup is outside the supported implementation scope; use the provider's official documentation for that part of an existing release process. Previously generated workflows are not migrated automatically. Review them against their provider's requirements before publishing again.
