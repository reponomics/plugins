# Workflow Guard 0.1.0

Workflow Guard checks GitHub Actions changes made through Claude Code's Write and Edit tools and blocks newly introduced action-pinning and top-level token-permission problems. This initial release is a mod implemented through function hooks, with no additional skills or setup required after installation.

- Require new external action and reusable-workflow references to use full 40-character commit SHAs.
- Require a top-level permissions block when a change introduces its absence, and stop new top-level write grants. Declare write permissions on the jobs that need them.
- Return findings to Claude so it can correct the change. Workflow files under `.github/workflows/` receive both checks; composite actions receive pinning checks only.
- Choose blocking or warning mode in `/config`, use explicit allow comments for exceptions, or manage a per-user ignore list with `/workflow-guard`. Adding an ignored path requires a command typed by the user.

The guard reports problems introduced by the change rather than repairing existing findings. Its line-based YAML checks cover common block and flow styles, but not every valid YAML construct. It does not inspect changes made through shell commands or other tools, verify that a pinned SHA exists, or check whether it matches a version comment.
